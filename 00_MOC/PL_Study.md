### C++ (메인)
- [[C++이란 무엇인가 — OOP 편한 C를 넘어서]] 🟢 — "OOP 편한 C" 입장의 정밀화, 무게중심은 RAII(자원 수명·결정적 정리) + 제네릭/템플릿(성능 손실 없는 타입 조립)
- [[C++ string — RAII로 포장한 문자열]] 🟢 — C 문자열 3대 아픔(타입 부재·길이 부재·배열 한계) → RAII 두 축으로 메움, Java String은 GC로 같은 문제 해결
- [[C++ 헤더와 include — 복붙·선언·구현·표준화]] 🟢 — #include=전처리 복붙, 헤더엔 선언만→컴파일(빈칸)→링크(구현 주소), 확장자 없는 헤더=std:: 표준판 표식
- [[C++ 계보와 표준화 — 벨연구소·Simula·ANSI·ISO]] 🟢 — 벨연구소(C 계열 본가), Simula(클래스 출처)·PARC(이름·비전), ANSI(ASCII·C89)→ISO(C++98)

## 비교 (Comparisons)

후반부에 본격화. 예정 주제:

- [[메모리 관리 비교]] — C 수동 / C++ RAII·스마트포인터 / Java GC
    - 씨앗: scanf 버퍼 오버플로, 배열 범위 검사 차이([[C 문법 조각 — 왼값·오른값과 scanf 경고]]), VLA의 스택 위험([[C 연산자 — 정체와 시퀀스 포인트]]), goto 자원정리 관용구([[C 제어문 — 점프로 본 분기·반복]]), RAII vs GC·try-finally([[C++이란 무엇인가 — OOP 편한 C를 넘어서]]), std::string 자동 반납 vs Java GC([[C++ string — RAII로 포장한 문자열]])
- [[OOP 모델 비교]] — 없음 / 다중상속 / 단일상속+인터페이스
    - 씨앗: 정적/동적 바인딩, C++ virtual([[정적·동적 바인딩과 컴파일타임·런타임]])
- [[컴파일·실행 모델 비교]]
    - 씨앗: C/C++(AOT) vs Java(바이트코드+JVM+JIT) 대비를 [[언어란 무엇인가 — 분류와 컴파일·실행 모델]]에서 이미 다룸; #include 복붙·링크 vs Java import·클래스패스([[C++ 헤더와 include — 복붙·선언·구현·표준화]])
- [[제네릭·템플릿 비교]]
    - 씨앗: 이터레이터(for-each의 엔진)는 C 포인터의 일반화 → STL 알고리즘이 모든 컨테이너에 도는 토대([[C 순회와 난수 — for-each·이터레이터와 랜덤]]); 템플릿(컴파일타임 타입별 생성) vs Java type erasure·박싱([[C++이란 무엇인가 — OOP 편한 C를 넘어서]]); 템플릿 구현이 헤더에 사는 이유([[C++ 헤더와 include — 복붙·선언·구현·표준화]])
- [[문자 인코딩 비교]] — 문자 ↔ 바이트 매핑: 아스키 1바이트(C char) vs 유니코드(Java char 2바이트), UTF-8/UTF-16
    - 씨앗: [[C 자료형 — 정수와 실수의 표현]]의 char 항목; C char 배열은 바이트 단위라 한글 글자수≠바이트수([[C++ string — RAII로 포장한 문자열]])
- [[문자열 비교]] — 문자열 '타입'으로서: C char 배열(약속) / C++ std::string(RAII) / Java String. 메모리 관리·`==` 의미·가변성
    - 씨앗: [[C++ string — RAII로 포장한 문자열]] (자동 메모리 관리, == 가 주소냐 내용이냐)
