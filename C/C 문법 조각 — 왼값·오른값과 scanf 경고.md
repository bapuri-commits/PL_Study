# C 문법 조각 — 왼값·오른값과 scanf 경고

> [!info] 출처
> 이 노트는 [[프로그래밍 기초 개념_ C ver]]의 토론에서 파생되었습니다. (2026-06-17)

## 핵심 요약
> 작지만 자주 부딪히는 C 문법 조각 셋. 왼값/오른값은 "주소를 가진 실체냐 임시값이냐", scanf 경고는 버퍼 오버플로 위험에 대한 MS의 잔소리, define vs const는 "전처리 문자 치환이냐 타입을 가진 진짜 변수냐"의 층위 차이다.

## 내용

### 왼값(lvalue)과 오른값(rvalue)
- 이름은 대입 `=`의 왼쪽/오른쪽에 올 수 있냐에서 왔다. 하지만 본질은 따로 있다.
- 핵심 기준은 "메모리상에 자기 주소를 가진, 식별 가능한 저장 공간인가"이다.
    - 왼값은 주소를 가진 실체다. 이름표가 붙어 계속 존재한다. `&`로 주소를 얻을 수 있다. (예: `x`, `arr[2]`. "배열 시작 주소 + 인덱스" 위치를 가짐)
    - 오른값은 주소 없이 잠깐 나타났다 사라지는 값이다. `&`로 못 가리킨다. (예: `10`, `b + 1`의 결과. 계산 중 잠깐 존재 후 증발)
- 컴파일과 연결하면, 왼값은 심볼 테이블에 주소가 잡히는 것이고 오른값은 그런 집이 없는 임시값이다. ([[언어란 무엇인가 — 분류와 컴파일·실행 모델]]의 "이름을 주소로" 단계 참조)
- C++ 메인에서 이동 의미론(move semantics)의 뿌리가 되는 개념이다.

### scanf 경고와 #define _CRT_SECURE_NO_WARNINGS
- 비주얼 스튜디오에서 `scanf`는 `C4996: ... may be unsafe` 경고를 띄운다.
- 그 이유는 `scanf("%s", name)`이 입력 길이 한계를 모르기 때문이다. 버퍼보다 긴 입력이 오면 그 너머 메모리까지 덮어쓰는데, 이게 버퍼 오버플로다. 옆 변수 손상이나 프로그램 붕괴를 일으키고, 고전적 해킹 통로가 된다.
- `#define _CRT_SECURE_NO_WARNINGS`는 "CRT 보안 경고를 끈다"는 스위치다. 위험을 없애는 게 아니라 경고만 숨긴다(알람을 끈 것).
- 이 경고는 MS 고유로(gcc는 안 띄움) 표준 C의 scanf와 MS 보안 철학의 충돌이다.
- 대응은 세 가지다. 학습용은 `_CRT_SECURE_NO_WARNINGS`로 끄기(가장 간편), `scanf_s` 쓰기(MS 전용, 이식성 낮음), `scanf("%4s", ...)`로 폭 제한(표준이고 안전). C++ 가면 `std::cin`으로 갈아타 scanf 자체를 거의 안 쓴다.

### #define vs const
- 핵심은 "층위가 다르다"는 것이다.
    - `#define MAX 100`은 전처리 단계(컴파일 전)에서 단순 문자 치환을 한다. 컴파일러가 보기도 전에 `MAX`를 전부 `100`으로 갈아치운다. (Ctrl+H 모두 바꾸기와 같음)
    - `const int max = 100;`은 진짜 변수다(주소와 타입 보유). 값 변경만 막힌 왼값이며, 컴파일러가 정식 변수로 인식한다.
- 차이가 낳는 결과는 아래 표와 같다.

| | `#define` | `const` |
|---|---|---|
| 처리 시점 | 전처리(컴파일 전) | 컴파일 |
| 정체 | 단순 문자 치환 | 진짜 변수(주소·타입) |
| 타입 검사 | 없음 | 있음 |
| 디버깅 | 이름 안 보임 | 추적됨 |
| 스코프 | 파일 전체 무차별 | 블록 단위 |
| 고유 능력 | 매크로·조건부컴파일·스위치 | (값 상수로서 안전) |

- `#define`의 고유 영역은 코드 조각 치환(`#define SQUARE(x) ((x)*(x))`), 컴파일 제어 스위치(`_CRT_SECURE_NO_WARNINGS`), 조건부 컴파일(`#ifdef`)이다. 이건 `const`로 불가능하다(const는 값일 뿐).
- 권장 — 단순 값 상수는 `const`(C++이면 `constexpr`)를 쓰고, `#define`은 const로 못 하는 일에만 쓴다.

## 코드
```c
// 왼값 / 오른값
int x;
x = 10;        // x는 왼값, 10은 오른값
// 10 = x;     // 불가: 오른값은 대입 왼쪽에 못 옴
int arr[5];
arr[2] = 100;  // arr[2]는 왼값 (&arr[2] 가능)

// scanf 안전성
#define _CRT_SECURE_NO_WARNINGS   // 경고만 끔(위험 자체는 남음)
scanf("%4s", name);               // 표준이고 안전: 폭 제한

// define vs const
#define MAX 100          // 전처리 치환, 세미콜론 없음
const int maxVal = 100;  // 타입 가진 진짜 변수
```

## 다른 언어에선?
- define vs const — 자바엔 `#define`이 아예 없다(전처리기 자체가 없음). 상수는 항상 `static final int MAX = 100;`처럼 진짜 상수(변수 계열)로만 만든다. C의 const 길만 있고 텍스트 치환의 길은 처음부터 차단한 것으로, "위험하고 헷갈리니 빼자"는 자바 철학이다.
- scanf와 버퍼 오버플로 — C는 배열 범위를 넘어가도 안 막는다. 자바는 범위를 넘으면 예외(`ArrayIndexOutOfBoundsException`)로 즉시 차단한다. 이 차이의 뿌리는 추후 메모리 관리 비교에서 다룬다.
- 관통하는 대비 재확인 — C는 자유를 주되 책임은 프로그래머에게, Java는 안전을 위해 위험을 제거한다.
