# C 비트 연산

> [!info] 출처
> 이 노트는 [[프로그래밍 기초 문법_ C ver]]의 토론에서 파생되었습니다. (2026-06-17)

## 핵심 요약
> 비트 연산의 핵심은 **정수를 "수"가 아니라 "on/off 스위치 묶음"으로 보는 관점 전환**이다. 이 위에서 두 기둥이 선다. (1) 플래그 — 여러 on/off를 정수 하나로 묶어 통째로 다루기(켜기 `|=` / 끄기 `&= ~` / 검사 `& FLAG` / 토글 `^=`). (2) 산술·판정 트릭 — `<<`/`>>`는 ×/÷ 2ⁿ, `& 1`은 홀짝, XOR은 `x^x=0`. 함정 둘을 조심해야 한다: ^는 토글이지 설정이 아니다, 그리고 비트 연산은 비교 연산보다 우선순위가 낮아 괄호가 필수다.

## 내용

### 관점 전환 — 정수는 "스위치 묶음"이다
- 비트 연산 활용의 9할은 이 한 줄에서 나온다: `int`는 그냥 **32개의 on/off 스위치가 일렬로 늘어선 것**이다. "수 13"이 아니라 "이 칸들이 켜진 패턴"으로 본다.
- 이 관점이 박히면 가장 흔한 활용인 **비트 플래그(마스크)**가 바로 따라 나온다.

### 플래그 — 4대 패턴
- 각 의미를 비트 한 칸에 배정한다. `1 << n`이 "n번 칸만 켜진 자"를 만든다.

```c
#define BOLD      (1 << 0)   // ...0001
#define ITALIC    (1 << 1)   // ...0010
#define UNDERLINE (1 << 2)   // ...0100
int style = 0;               // 전부 off
```

- **켜기 — `style |= FLAG;`** (OR). 1이 하나라도 있으면 1이라, 켜진 자리들이 합쳐진다. 이미 켜진 칸은 그대로 → 안전하게 "추가".
    - `style = BOLD | UNDERLINE;` 처럼 **이름으로 합쳐 쓴다.** `style = 5;`(암산으로 십진수 박기)는 작동은 해도 의도가 증발하고, 플래그 비트가 바뀌면 조용히 틀린다.
- **끄기 — `style &= ~FLAG;`** (`~`로 그 칸만 0인 마스크를 만들어 AND). `~BOLD = ...1110`은 "BOLD 칸만 구멍 뚫린 체". AND로 통과시키면 그 칸만 떨어지고 나머지는 살아남는다.
- **검사 — `if (style & FLAG)`** (AND 마스킹). 보고 싶은 칸만 1로 세운 마스크를 대고 나머지를 0으로 가린다. 켜져 있으면 그 칸 값(비0)→참, 꺼져 있으면 0→거짓.
    - 주의: `if (style >> 1)`로 검사하면 **안 된다.** shift는 위쪽 비트까지 끌고 내려와 섞이므로, 그 칸만 격리하지 못한다. 격리는 AND의 일.
- **토글 — `style ^= FLAG;`** (XOR). 켜져 있으면 끄고 꺼져 있으면 켠다. 같은 걸 또 XOR하면 원위치.

> [!example] 리눅스 권한 = 정확히 이 메커니즘
> `chmod 755`의 숫자가 비트 플래그다. `r=4(1<<2) w=2(1<<1) x=1(1<<0)`, 한 자리(소유자/그룹/기타)가 3비트. `7=111=rwx`, `5=101=r-x`. 커널은 `mode & S_IRUSR`처럼 **AND 마스킹**으로 권한을 검사한다. 8진수 한 자리가 정확히 3비트라 권한 묶기에 딱 맞아 8진법을 쓴다.

- **플래그의 실익**(왜 `bool` 여러 개 대신 이걸 쓰나):
    - **(1순위) 표현·전달이 한 덩어리** — 옵션 여러 개를 인자 하나로 통째 전달. OS API가 다 이 방식(`open`의 `O_RDONLY | O_CREAT`).
    - **(상황별) 메모리** — `bool` 8개 ≈ 8바이트 vs 비트 8개 = 1바이트. [[C 자료형 — 정수와 실수의 표현]]의 "대량 데이터·임베디드"에서 효자.
    - **속도** — CPU 단일 명령이라 빠르지만 요즘 체감 이득은 거의 없음(부수입).

### 산술·판정 트릭
- **`x << n` = `x * 2ⁿ`, `x >> n` = `x / 2ⁿ`(정수)** — 10진수 자리 밀기가 ×10이듯 2진수 한 칸은 ×2.
    - 단, **속도 목적의 직접 shift는 비추.** 요즘 컴파일러가 `x*8`을 알아서 `x<<3`으로 바꾼다(가독성만 손해). 진짜 쓸모는 **2의 거듭제곱 단위**를 다룰 때(`1KB = 1<<10`, 플래그 정의 `1<<n`).
    - ⚠️ shift는 공짜로 무한히 못 민다. 밀어낸 비트가 타입 범위를 넘으면 흘러넘쳐 사라진다(`1<<31`을 `int`에 하면 부호 비트와 엮인 지뢰 → 막힌 것 참조).
- **`x & 1` = 홀짝 판정** — 2진수 맨 끝 비트만 "1의 자리(2⁰)"이고 그 위는 전부 짝수. 홀짝 정보는 끝 비트에만 있으니 마스크 `1`로 그 칸만 떼면 끝. (`% 2`와 달리 음수 부호 문제가 없어 더 안전한 경우가 있음.)
- **XOR 성질** — `x ^ x = 0`(모든 비트가 같아 전부 0), `x ^ 0 = x`. 이 둘이 XOR을 특별하게 만든다.
    - 토글의 원리(`^= FLAG`).
    - 고전 문제 — "다 두 번씩 있고 하나만 한 번"인 배열에서 전체를 XOR로 누적하면 쌍들은 0으로 사라지고 외톨이만 남는다(O(1) 메모리).

### 함정 둘 (제일 자주 당함)
- **함정 1 — 토글(`^`) vs 설정 혼동.** `^`는 "뒤집기"라 결과가 현재 상태에 의존한다. "무조건 켜기/끄기"에는 못 쓴다.
    - 예: EXEC를 켜려고 `perm ^ EXEC` 했는데 이미 켜져 있으면 오히려 꺼진다.
    - 설정의 정석은 상태 무관하게 결정적인 조합: **확실히 끄고(`& ~`) 확실히 켜기(`|`).**
        - `perm = (perm & ~WRITE) | EXEC;` — WRITE를 확정 0, EXEC를 확정 1. 현재 상태가 뭐든 결과 동일.
    - 정리: 켜기 `|`, 끄기 `& ~` (결정적) / 토글 `^` (상태 의존). 목적이 "뒤집기"일 때만 `^`.
- **함정 2 — 우선순위.** **비트 연산(`&` `|` `^`)은 비교 연산(`==` 등)보다 우선순위가 낮다.**
    - `x-1 & x == 0`은 `(x-1) & (x == 0)`으로 읽혀 거의 항상 참이 되는 조용한 버그.
    - 그래서 **비트 연산은 습관적으로 괄호**로 묶는다: `(x & (x-1)) == 0`.
    - 이건 C의 유명한 설계 실수로 꼽힌다(우선순위가 거꾸로). [[C 연산자 — 정체와 시퀀스 포인트]]의 우선순위 주의와 같은 맥락.

### 종합 예 — 2의 거듭제곱 판정
- 2의 거듭제곱은 2진수로 `1000…0`처럼 **1이 딱 하나**다. `x - 1`을 하면 그 1이 0이 되고 아래가 전부 1로 켜진다(`1000 - 1 = 0111`). 둘을 AND하면 겹치는 칸이 없어 0.

```c
// x가 2의 거듭제곱인가
x != 0 && (x & (x - 1)) == 0
```

- `x != 0`이 필요한 이유 — `0`은 `(0 & -1) == 0`으로 참이 나오지만 2의 거듭제곱이 아니다.
- 괄호가 필요한 이유 — 함정 2(우선순위).

## 코드
```c
#define BOLD      (1 << 0)
#define ITALIC    (1 << 1)
#define UNDERLINE (1 << 2)

int style = 0;
style |= BOLD | UNDERLINE;   // 켜기 (합쳐 추가)
style |= ITALIC;             // 기존 유지하며 추가
style &= ~BOLD;              // 끄기 (그 칸만 0, 나머지 유지)
if (style & ITALIC) { /* ITALIC 켜짐? — AND 마스킹 */ }
style ^= UNDERLINE;          // 토글 (켜졌으면 끔, 꺼졌으면 켬)

// 권한 설정의 정석: 확실히 끄고 확실히 켜기 (XOR 아님)
perm = (perm & ~WRITE) | EXEC;

// 산술/판정
int times8 = x << 3;         // x * 8
int isOdd  = x & 1;          // 1이면 홀수
int isPow2 = (x != 0) && ((x & (x - 1)) == 0);  // 괄호 필수
```

## 다른 언어에선?
- 연산자 `& | ^ ~ << >>`는 Java도 동일하다. 자바엔 추가로 **`>>>`(부호 없는 오른쪽 shift)**가 있어 부호 비트를 안 끌고 와 0으로 채운다. C엔 `>>>`가 없고, 대신 피연산자를 `unsigned`로 두면 `>>`가 그 역할을 한다(→ 막힌 것의 signed/unsigned shift).
- 자바는 플래그를 타입 안전하게 다루는 `EnumSet`을 표준 제공한다(내부는 비트마스크). C는 `#define` + 정수로 직접 굴린다("자유 vs 안전"의 그 대비, [[C 자료형 — 정수와 실수의 표현]]).

## 막힌 것 / 의문
- **`signed` vs `unsigned` shift** — `>>`가 부호에 따라 동작이 갈린다(음수에서 산술 shift로 부호 비트를 채우는지 vs 논리 shift로 0을 채우는지). 2의 보수([[C 자료형 — 정수와 실수의 표현]])와 직결되는 순수 C 문법. 다음 패스에서 이 노트 안에 채울 자리.
- **비트필드** (`struct { unsigned flag : 1; };`) — C 고유 문법. 실무에선 플래그 방식을 더 많이 쓰지만 문법으로서 정리할 거리. 다음 패스.
- **shift 오버플로** (`1 << 31` 등) — 포인터/오버플로를 본격적으로 다룰 때 부호 비트와 엮어 정리.
- **알고리즘·자료구조 응용** (popcount, `x & -x`, 비트마스크 DP, 비트셋, 블룸 필터 등) → 외부 학습 경계라 [[비트 연산 — 알고리즘·자료구조 응용]]으로 분리. 알고리즘 정리와 연결할 때 재개.
