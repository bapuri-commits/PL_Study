# C++ 계보와 표준화 — 벨연구소·Simula·ANSI·ISO

> [!info] 출처
> 이 노트는 [[프로그래밍 기초 개념_ C++ ver]]의 토론에서 파생되었습니다. (2026-06-18)

## 핵심 요약
> C++의 역사적 뿌리는 세 갈래다. (1) **벨연구소** — C 계열의 본가(Unix·C·C++가 모두 여기서 났다). (2) **Simula** — 클래스·상속·소멸자라는 *언어 장치*의 출처이자 C++이 직접 베낀 곳("object-oriented"라는 *이름과 비전*은 따로, 제록스 PARC의 Smalltalk). (3) **ANSI → ISO** — 표준화의 흐름. ASCII와 "ANSI C"(C89)가 ANSI 작품이고, C++은 ISO 표준(C++98에서 `std::`·헤더 정리). 패러다임 진화사 자체는 외부 학습 영역이라 질문 노트로 분리한다.

## 내용

### 벨연구소 (Bell Labs) — C 계열의 본가
- AT&T 산하의 기초연구소. PL 역사에 단골로 나오는 건, 이 프로젝트가 다루는 언어들이 거의 다 여기서 났기 때문이다 — **Unix**(켄 톰슨·데니스 리치, 1969~), **C**(리치, 1972~), **C++**(비야네 스트롭스트룹, 1979~).
- 언어 밖 업적도 거대하다 — **트랜지스터**(1947), 섀넌의 **정보이론**(1948, 비트·압축·통신의 토대), 레이저·CCD 등 노벨상이 여럿 나왔다. (지금은 여러 인수합병을 거쳐 노키아 산하로 이어진다.)
- 의미 — C도 C++도 "같은 지붕 아래"서 났다. C++이 C 호환·유산을 짊어진 게 우연이 아닌 이유.

### Simula — 클래스라는 *장치*의 출처
- C++의 클래스·상속·소멸자는 노르웨이의 **Simula**(올레요한 달·크리스텐 뉘고르, 1960년대)에서 왔다. Simula는 PL을 만들려던 게 아니라 **시뮬레이션** 도구로 출발했는데(항구의 배 같은 걸 모델링), 시뮬레이션의 본질이 "상태와 행동을 가진 객체들의 상호작용"이라 언어가 그것을 직접 표현하게 만들며 클래스·객체·상속을 낳았다.
- 결정적으로 — **스트롭스트룹이 C에 클래스를 얹을 때 본 건 Smalltalk가 아니라 Simula다.** → [[C++이란 무엇인가 — OOP 편한 C를 넘어서]]에 심어둔 "Simula에서 클래스·소멸자를 가져왔다"는 연결고리가 여기서 닫힌다.
- 한편 "object-oriented"라는 **말**과 "모든 것은 객체, 계산은 메시지 전달"이라는 **순수 비전**은 별개로 제록스 **PARC**(팔로알토 연구소)의 앨런 케이/**Smalltalk**(1970년대)에서 나왔다. 즉 **이름·비전 = PARC, 언어 장치 = Simula**로 갈린다. (원본글 질문1-3 "OOP는 PARC에서?"가 절반만 맞은 이유.)
- ⚠️ 절차→객체→함수형→관점지향의 **진화사 자체는 [[지침]]의 외부 학습 경계**(OOP)다. 흐름 요약은 상기용으로 [[패러다임 진화사 — 절차·객체·함수형·관점지향]]에 분리해 둠.

### ANSI → ISO — 표준화
- **ANSI**(American National Standards Institute, 미국 국가표준협회)는 표준을 직접 쓰기보다 미국 표준을 **조율·인증**하는 우산 기관이다. PL과 두 군데서 만난다.
    - **ASCII** — 원래 ANSI 표준(X3.4). → [[C 자료형 — 정수와 실수의 표현]]의 "char = 1바이트 정수 + 아스키 해석"이 바로 이 표준.
    - **"ANSI C"** — C의 첫 공식 표준(1989, C89/C90)을 ANSI가 만들어 그렇게 불린다. 그 전엔 "리치의 책대로"가 사실상 표준이던 것을 문서로 못박은 것.
- 이후 국제표준은 **ISO**가 이어받았다. C++은 ISO 표준이고 — [[C++ 헤더와 include — 복붙·선언·구현·표준화]]의 "1998년 첫 표준화(`std::`·확장자 정리)"가 바로 ISO **C++98**이다. ANSI(미국) → ISO(국제)로 바통이 넘어간 흐름.

## 다른 언어에선?
- **Java**(1995, 썬 마이크로시스템즈)는 벨연구소 계열이 아닌 다른 혈통이지만, C/C++ 문법을 **의도적으로 닮게** 만들어 진입장벽을 낮췄다. 표준화도 ISO/ANSI가 아니라 자체 프로세스(JCP)로 굴린다. → 추후 Java 시작할 때.
